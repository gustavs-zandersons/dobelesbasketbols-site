# Dobeles basketbols — tournament site

Public website for the 2026/27 **Dobeles Basketbola čempionu kauss** and the
**Jelgavas Sporta servisa centra Izaicinājuma kauss**: results, schedule,
calendar, standings, brackets and game box scores. Latvian only, mobile first.

> **Status: test version with made-up data.** Team names and logos are real;
> every score, player and statistic is invented. The site uses a fixed mock
> date (10 March 2027 — Dobele semifinals after game 1, Challenge Cup
> semifinals after the first leg). The real data sync from basket.lv comes later.

Live (once GitHub Pages is enabled): https://gustavs-zandersons.github.io/dobelesbasketbols-site/

On the home page, **Dalīties** next to the next round opens the round posters:
a 4:5 feed post (Facebook, Instagram) and a 9:16 Story/Reel. Phones open the
system share sheet; computers download the image. (Sharing and downloading work
on the live site, not inside the Claude preview.)

Add `?demo` to the address (e.g. `/?demo#dobele`) to show the prototype bar and
jump between season stages: pre-season, group stage, K group, playoffs, season end.

## How it works

- **Static site, no server.** One HTML page with styles, scripts and season data
  inlined, plus `assets/` (cup, team and sponsor logos).
- **Standings and brackets are calculated, never typed.** `src/engine.js` holds the
  tournament rules (points 2/1/0, head-to-head tiebreakers, K group carry-over,
  best-of-3 semifinals, two-leg Challenge Cup ties, projected bracket) and derives
  everything from the game results.
- **Round posters are drawn in the browser** (`src/poster.js`, canvas) from the
  round's games: last season's poster layout, a photo from the pool, the
  sponsor logos and the photo/video notice. Nothing is stored; a new round
  gives new posters automatically.
- **`src/sample-data.json`** is the mock season, generated by `tools/gen-season.js`
  (one hall per round, at most 4 games, box scores that add up to each score).

```
src/
  template.html      page skeleton (Latvian copy)
  styles.css         both cup themes (Dobele blue/yellow, Jelgava maroon/blue)
  engine.js          tournament rules → tables, brackets, rounds
  app.js             renders home, game, calendar and standings pages, share pop-up
  poster.js          draws the round posters (feed 1080×1350, story 1080×1920)
  sample-data.json   mock 2026/27 season
  sponsors.json      sponsor list and order (generated)
  poster-photos.json photo pool for the posters (generated)
tools/
  build.py           builds dist/ (GitHub Pages) or dist-preview/
  prepare_assets.py  web copies of sponsor logos and poster photos
  gen-season.js      regenerates the mock season
  check.js           sanity checks run in CI
assets/              web-optimised logos and poster photos (published)
design/sponsors/     original sponsor logo files (not published)
.github/workflows/   build + deploy to GitHub Pages
```

## Working on it locally

```bash
python3 tools/build.py              # → dist/index.html, open it in a browser
node tools/check.js                 # sanity checks
node tools/gen-season.js > src/sample-data.json   # regenerate the mock season
```

## Sponsors and poster photos

- **Sponsor logos:** originals live in `design/sponsors/<id>.png`; the list and
  order are in `tools/prepare_assets.py`. Run `python3 tools/prepare_assets.py sponsors`
  to make the web copies. The footer and the posters size every logo to the
  same visual weight automatically.
- **Poster photos:** one shared pool for both cups. Each round gets the next
  photo in the pool (the same one for everyone sharing that round). Add photos with
  `python3 tools/prepare_assets.py photos <files…>`; they are resized to 1600 px
  and listed in `src/poster-photos.json`. Landscape action shots work best; the
  top of the poster is a wide strip and the photo is darkened automatically.
  The current pool has one stand-in photo taken from last season's poster.

## Deployment

Every push to `main` builds the site, runs the checks and publishes it to GitHub
Pages. Pull requests only build and check.

One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
